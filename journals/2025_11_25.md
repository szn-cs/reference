		- #+BEGIN_QUOTE
		    **Building a production agent — recommended architecture**  
		  - **Design tools first**: think in terms of the *actions* your agent needs (e.g., fetchInbox, createTicket, run_test). Make those tools small, typed, and testable.
		  - **Least privilege**: only allow the tools the agent needs and set an appropriate permissionMode. Use hooks for safeguards on high-risk tools.
		  - **Session & memory strategy**:
		    decide what stays in short-term session context vs. longer-term memory   
		    (CLAUDE.md or a separate memory tool). Use explicit compaction and   
		    summarize or checkpoint memory to avoid context blowups.  
		  - **Testing harness**:
		    run the agent locally with canned prompts, simulate tool failures, and   
		    collect logs. The SDK has streaming examples and interactive examples   
		    (IPython) to accelerate development.  
		  - **Monitoring & observability**: instrument tool use, errors, and Hook decisions so you can detect drift, unsafe behavior, and performance regressions

	- ### Notes:
		- Coding agent development notes:
			- Symptom: Agents attempting broad file writes or shell commands.
				- Fix: Tighten allowlists; add confirmations; expand PreToolUse checks; rotate credentials.
			- Symptom: Context drift across long sessions.
				- Fix: Reset per-subagent context; store only compact global state; rely on summaries/retrieval; reinforce CLAUDE.md.
			- Symptom: Hooks misbehaving or conflicting.
				- Fix: Validate and version hooks; add deterministic tests; isolate changes to staging; deploy behind flags.
			- Symptom: Tool outputs inconsistent or flaky.
				- Fix:
				  Add retries with jitter; verify inputs/outputs; instrument latencies; 
				  fail fast and escalate to a human when anomalies exceed thresholds.
			- Symptom: Prompt injection via tool outputs.
				- Fix: Sanitize external inputs; enforce MCP security guidance (authN/authZ, TLS, sandboxing); restrict which outputs become agent-readable context
